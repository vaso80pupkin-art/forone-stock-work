# FORONE Stock Work — состояние внедрения

## Выполнено в `forone-stock-work`

- [x] Первый репозиторий `forone-stock` и офисная исходная Google Таблица не изменяются; новая версия изолирована в `forone-stock-work` и использует отдельную приватную рабочую копию.
- [x] Двусторонний поток разделён безопасно: операции телефона записываются только в рабочую копию (`FORONE_Операции` и `FORONE_Остатки`), а офисная таблица подключается отдельным Script Property `FORONE_SOURCE_SPREADSHEET_ID` только для чтения.
- [x] `FORONE_setup()` сохраняет ID связанной рабочей копии в приватные Script Properties. При отсутствующем source ID, совпадении source/target или защищённом старом ID настройка прекращается до создания листов.
- [x] Сервер перед выдачей остатков и обработкой операций обновляет рабочую копию из офиса; Apps Script trigger запускает фоновую сверку примерно каждые 15 минут.
- [x] Текущая вкладка выбирается по календарному месяцу и году: для 17.11.2026 — `Октябрь-Ноябрь`; при отсутствии новой декабрьской вкладки остаётся последний действительный лист; после появления `Ноябрь-Декабрь` выбирается она; для января 2027 предусмотрен выбор `Декабрь-Январь 2027`.
- [x] PWA загружает остатки при старте и возвращении на экран, после восстановления сети, затем примерно каждые 15 минут. После слияния серверных данных каталог перерисовывается, а офлайн-очередь операций остаётся на устройстве до отправки.
- [x] ID новых частных таблиц не захардкожены в публичном клиенте/серверном коде; прямой Google-импорт по умолчанию отключён.
- [x] Автопроверки: 141 серверная + 113 клиентских = 254; включая source/target изоляцию, запуск Web App без активной книги, защиту legacy ID, GET/POST-сверку, календарный переход 2026–2027 и авто-pull клиента.
- [x] Документация обновлена: `README.md`, `SYNCHRONIZATION.md`, `TESTING.md`, `CHANGELOG.md`.

## Осталось выполнить вручную в Chrome — требуется владелец Google-аккаунта

- [ ] Открыть приватную рабочую копию по ссылке, выданной отдельно владельцу, и из неё перейти **Расширения → Apps Script**. Не открывать для установки кода офисный источник или таблицу первого репозитория.
- [ ] В Script Properties задать `FORONE_SOURCE_SPREADSHEET_ID` (ID офисной таблицы; значение будет указано отдельно владельцу) и длинный `FORONE_SHARED_SECRET`. `FORONE_SPREADSHEET_ID` вручную не вводить: `FORONE_setup()` запишет ID связанной копии.
- [ ] Вставить `FORONE_Sync_v2.gs`, сохранить и запустить `FORONE_setup()`. Владелец подтверждает доступ на чтение офисного источника и запись только в рабочую копию; убедиться, что `FORONE_Остатки`, `FORONE_Операции` и `FORONE_Ошибки` появились именно в копии.
- [ ] Запустить `FORONE_selfTest()`, развернуть Web App 2.1.0 (исполнение от имени владельца; доступ по ссылке) и прислать URL `/exec` в чат.
- [ ] После получения `/exec` проверить ping и актуальные остатки, выполнить идемпотентную тестовую операцию только на копии и отдельно подтвердить, что офисный источник не менялся.
- [ ] После появления вкладки бухгалтерии на декабрь/январь сверить в живом Web App автоматический выбор соответствующего листа; локальные календарные сценарии уже проходят.
