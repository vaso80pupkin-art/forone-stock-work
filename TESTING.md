# Как это проверено

Два набора автотестов и учебный сервер запускаются локально на Node.js без внешних зависимостей. Автотесты используют только фиктивные ID и тестовые таблицы — они не читают и не меняют Google Drive владельца.

```bash
cd tests
node gs-tests.js        # 141 проверка Apps Script
node sync-tests.js      # 113 проверок клиента и автообновления
node mock-webapp.js 8099 # учебный Web App на реальном коде .gs
```

Итого: 254 автоматические проверки.

## `gs-harness.js` — эмулятор Google Apps Script

`vm`-контекст с тестовыми `SpreadsheetApp`, `LockService`, `PropertiesService`, `Utilities` и объектами событий `doGet` / `doPost`. В тестах исполняется настоящий `FORONE_Sync_v2.gs`, а не его пересказ. Source и target — две разные фиктивные книги.

Проверяются защита от записи в источник, приватные Script Properties, остановка `FORONE_setup()` при отсутствующем или совпадающем source ID, выбор текущего месячного листа, обновление рабочей копии перед GET/POST, журналы, конфликт и слияние остатков, idempotency, блокировка параллельных операций, `FORONE_setup()` и `FORONE_selfTest()`.

Календарные проверки подтверждают: на 17.11.2026 выбирается `Октябрь-Ноябрь`; если вкладки `Ноябрь-Декабрь` ещё нет, остаётся последний действительный лист; после появления такой вкладки в декабре выбирается она; на январь 2027 выбирается `Декабрь-Январь 2027`.

## `sync-tests.js` — клиент без браузера

`sync-queue.js` загружается в `vm` с подставными `fetch`, `localStorage`, таймерами и состоянием приложения. Проверяются 20 000 уникальных ID операций в секунду, офлайн-очередь, повторы, отклонения, отмена и обратная операция, слияние дублирующихся артикулов, сохранность локальных операций и загрузка серверных остатков.

Отдельные проверки покрывают автоматический GET `stock` при запуске и возврате приложения на экран, обновление интерфейса после слияния, запрос при восстановлении сети и пропуск лишнего запроса внутри 15-минутного интервала.

## `mock-webapp.js` — сквозная проверка

Учебный сервер поднимает настоящий `FORONE_Sync_v2.gs` на `http://localhost:<порт>/exec` с тестовыми листами и раздельными source/target-книгами. Служебные ручки позволяют проверить HTML-ответ, экран входа, HTTP 500, BUSY, таймаут, занятую блокировку, изменение источника, синхронизацию, содержимое рабочих листов и reset стенда.

Так проверяется, что приложение находит позицию с повторяющимся артикулом, не теряет офлайн-операцию и после сверки сходится с сервером. Сквозная проверка не заменяет финальную проверку Web App в Google.

## Перед запуском на копии Google Таблицы

1. В Chrome открыть приватную рабочую копию по отдельной ссылке владельца. Не открывать офисный источник или таблицу первого репозитория для установки кода.
2. В связанном Apps Script добавить `FORONE_SOURCE_SPREADSHEET_ID` со значением ID офисной таблицы и `FORONE_SHARED_SECRET` с длинным случайным ключом. `FORONE_SPREADSHEET_ID` вручную не задавать: `FORONE_setup()` сохранит ID открытой рабочей копии. Если source ID отсутствует или указывает на target, setup должен остановиться до создания листов.
3. Вставить `FORONE_Sync_v2.gs`, запустить `FORONE_setup()` и разрешить доступ. Он должен создать только в рабочей копии листы `FORONE_Остатки`, `FORONE_Операции`, `FORONE_Ошибки`, загрузить свежий источник и установить триггер примерно на 15 минут.
4. Запустить `FORONE_selfTest()`, затем развернуть Web App версии 2.1.0 (исполнение от имени владельца; доступ для телефона — «Все, у кого есть ссылка»). Проверить соединение в приложении и убедиться, что ping сообщает `2.1.0`.
5. Только на копии выполнить тестовый приход или расход на одну единицу, затем сверить строку в `FORONE_Операции`, остаток в `FORONE_Остатки` и статус на телефоне. Отдельно убедиться, что офисный источник не изменился.
6. Проверить очередь: оформить тестовую операцию без интернета, восстановить связь и дождаться отправки. На открытом телефоне остатки должны загружаться при старте/возврате в приложение и далее примерно каждые 15 минут.
7. Когда бухгалтер создаст вкладку `Ноябрь-Декабрь`, сервер должен выбрать её в декабре; в январе 2027 — вкладку для `Декабрь-Январь 2027`. Триггеры Google Apps Script работают приблизительно, а не поминутно.
