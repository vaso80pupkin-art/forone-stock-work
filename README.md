# FORONE.KZ · Склад

Публичный сайт: [https://vaso80pupkin-art.github.io/forone-stock-work/](https://vaso80pupkin-art.github.io/forone-stock-work/). GitHub Pages публикуется из корня ветки `main`.

## Изолированный тестовый стенд

Первый репозиторий [`forone-stock`](https://github.com/vaso80pupkin-art/forone-stock) и офисная исходная таблица не меняются. Эта версия использует отдельную приватную копию Google Таблицы; прямую ссылку на неё владелец получает отдельно в сообщении, ID таблиц не публикуются в репозитории.

`FORONE_Sync_v2.gs` пишет только в связанную рабочую копию, ID которой сохраняется в приватных Script Properties при `FORONE_setup()`. ID офисного источника задаётся там же и используется только для чтения. Локальные данные, настройки и кеш PWA также отделены от первой версии. На новом устройстве прямой Google-импорт выключен до явной настройки.

Мобильное одностраничное приложение (PWA) для складского учёта и проверки наличия
декоративных бамбуковых панелей, луверов и профилей.

Работает на телефоне без интернета, а операции за смену отправляет в рабочую копию через Apps Script Web App. Сервер регулярно сверяет рабочую копию с офисной таблицей, не записывая в офисный источник.

## Что открывается первым

Приложение — обычная папка с файлами. Чтобы посмотреть его в браузере, поднимите любой
статический сервер в этой папке:

```bash
python3 -m http.server 8080
# затем открыть http://localhost:8080
```

На телефоне: открыть адрес, добавить на главный экран (Chrome предлагает «Установить
приложение»). Данные хранятся в localStorage этого устройства, поэтому база не теряется
при закрытии вкладки и работает в офлайне.

## Как устроен учёт

* **Остаток** — сколько физически лежит на складе.
* **Резерв** — сколько зарезервировано под объект или бронь клиента.
* **Доступно** = остаток − резерв. Расход и списание на замер проверяются по доступному.
* **Операция за смену** — приход, расход или списание на замер. Каждая операция получает
  уникальный `operationId`; повторная отправка не приводит к двойному списанию.
* **Позиция** задаётся тройкой «артикул + название + категория». В реальной базе FORONE один
  артикул встречается в нескольких позициях (например `H234-YP` — и лувер, и панель),
  поэтому одного артикула для сопоставления недостаточно.

## Синхронизация с Google Таблицей

Полное руководство — в [`SYNCHRONIZATION.md`](SYNCHRONIZATION.md): установка Web App,
ключ доступа, как приложение находит позицию, что делать при отклонении операции складом,
таблица статусов и кодов ошибок.

Коротко:

1. В таблице создаётся Web App из файла `FORONE_Sync_v2.gs` (запуск `FORONE_setup()`,
   публикация как веб-приложение).
2. В приложении (кнопка `ⓘ` → блок «Отправка операций в Google Sheets (запись)») вставляются
   URL веб-приложения и ключ доступа, включается тумблер синхронизации.
3. Кнопка «Проверить соединение» показывает версию сервера и число позиций,
   «Сверить остатки» подтягивает свежие остатки. Автосверка выполняется при запуске и возвращении приложения на экран, а также примерно каждые 15 минут.
4. Дальше операции уходят сами: при появлении интернета, по таймеру, кнопочкой
   «Отправить сейчас» или кнопкой «↻ Повторить» у конкретной записи журнала.

## Тесты

```bash
cd tests
node gs-tests.js      # серверная логика Apps Script: 142 проверки
node sync-tests.js    # клиентская очередь и автообновление остатков: 113 проверок

```

Подробности — в [`TESTING.md`](TESTING.md).

## Резервная копия

`ⓘ` → «Резервная копия и перенос базы»: выгрузка JSON со всем каталогом, журналом смены и
очередью неотправленных операций, восстановление на другом телефоне. Перед переносом
убедитесь, что очередь пуста (жёлтая пилюля в шапке не видна) — иначе операция уйдёт
с нового устройства дважды.
